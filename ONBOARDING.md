## 1. О курсе

Курс читают эксперты Авито. Большинство студентов уже что-то пробовали с AI на любительском уровне и вайбкодили, поэтому наша задача не научить «пользоваться нейросеткой», а показать, как AI встраивается в повседневную работу инженера на всех этапах SDLC, и отработать это на практике.

**Сквозной проект.** Через весь курс студент ведёт один проект по собственному выбору, — развивая его от идеи до продакшена. Каждая неделя добавляет новый слой.

**Каркас курса — EJM.** Engineer Journey Map связывает конкретный AI-инструмент с реальным этапом разработки: требования → дизайн → реализация → тестирование → CI/CD → эксплуатация. Это не одна лекция, а сквозная структура всего курса.

**Что формируем у студента.** Мышление «AI-augmented engineer»: инженер выступает архитектором и тимлидом для своих AI-ассистентов — ставит задачи через промпт-инжиниринг, управляет контекстом (MCP, правила проекта), проводит код-ревью сгенерированного кода и автоматизирует процессы, а не только пишет код.

## 4. Онбординг по шагам

### Общая часть — для всех

1. Прочитать этот документ и README курса.
2. Получить доступы: `【ЗАПОЛНИТЬ: GitHub-организация, ключи LLM (OpenRouter/Vsellm), N8N, доступ к записям ktalk, рабочее пространство (Notion/Drive)】`.
3. Посмотреть записи беты по своим темам (раздел «Материалы и записи»).
4. Прийти на встречу команды курса — `【ЗАПОЛНИТЬ: дата/ссылка】`.

### Дополнительно — для семинаристов

1. Получить материалы практики + план её проведения: `【ЗАПОЛНИТЬ: где лежат — папка practices/NN/ в репозитории / Notion】`.
2. Посетить / посмотреть встречу с автором практики по каждому семинару (бриф, подводные камни).
3. Прогнать практику «на себе» до занятия — пройти весь цикл, как это будет делать студент.
4. Договориться о поддержке во время занятия: `【ЗАПОЛНИТЬ: будет ли ассистент, как эскалировать технические сбои】`.

### Дополнительно — для ревьюеров

1. Встреча с кураторами: сколько работ, какие критерии, разбор чек-листа проверки.
2. Изучить эталонные решения и руководства для преподавателей (`solutions/`, `README_INSTRUCTORS.md`).
3. Зафиксировать процесс: где брать работы, где выставлять оценки, срок возврата — `【ЗАПОЛНИТЬ: инструмент и дедлайн】`.
4. Сверить понимание рубрики на 1–2 работах вместе с куратором или другим ревьюером (калибровка).

## 5. Формат практики (для семинаристов)

**Длительность: 90 минут + домашнее задание.** Каркас занятия — тот же цикл, которому учим студентов:

- **Контекст.** Напоминаем, где мы в проекте и какой артефакт/фичу делаем сегодня.
- **Задача.** Ставим агенту задачу структурированно (R.C.T.F. / правила проекта).
- **Ревью.** Критически смотрим на то, что сгенерировал AI: риски, стиль, тесты, edge cases.
- **Уточнение.** Итеративно дорабатываем — «первая версия редко идеальна».

## 6. Проверка домашних работ (для ревьюеров)

**Ориентир по времени: 15–20 минут на студента.** Каждая практика сопровождается рубрикой, эталонным решением и чек-листом.

### Что проверяем

- Артефакты требований.
- Понимание, а не «AI-слоп»: студент должен объяснить, что и зачем сделал агент.
