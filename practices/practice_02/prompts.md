# Журнал экспериментов Практики 2

- Выбранный слабый артефакт Практики 1: [`tests_load.md`](../practice_01/tests_load.md) — нагрузочные проверки.
- Что в нём нужно улучшить: пороги местами непроверяемы («точка, после которой p95 растёт нелинейно»); расчёт потолка (40 потоков / 3 с ≈ 13 RPS) никто не пересчитывал, а оба множителя — необъявленные допущения; условия прогона не зафиксированы, поэтому два инженера получат разные цифры; способ моделировать LLM выбран без разбора альтернатив; часть чисел не выводится ни из одного файла Практики 1; формулировки требований расходятся с [`tests_integration.md`](../practice_01/tests_integration.md).
- Исходное состояние артефакта: [`tests_load_baseline.md`](tests_load_baseline.md) — копия файла Практики 1 на момент начала Практики 2. Каждая техника кладёт свою исправленную версию рядом со своим экспериментом (`<техника>/tests_load.md`), поэтому вклад каждой техники виден отдельным diff'ом против исходника. Сводный результат всех шести техник и четырёх кругов ревью — [`tests_load_final.md`](tests_load_final.md); он перенесён в действующий артефакт Практики 1 [`practices/practice_01/tests_load.md`](../practice_01/tests_load.md).
- Как поймём, что изменение полезно: каждая ячейка «Допустимый предел» содержит число с единицей измерения и переводится в `assert` без домысливания; каждое число либо имеет ссылку на источник, либо явно помечено допущением с указанием, чем закрывается; инженер, не писавший файл, воспроизводит прогон по документу без устных пояснений.
