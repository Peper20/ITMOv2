# Unit-проверки

Проверяем изолированно: без сети, без реального LLM, на стабе порта `LLM` из [`TRAINING_PR.diff`](TRAINING_PR.diff). Каждая строка привязана к правилу репозитория из [`CASE.md`](CASE.md).

| Требование или правило | Что проверяем изолированно | Вход | Ожидаемый результат | Evidence |
|---|---|---|---|---|
| `SEC-1` | `redact()` вырезает GitHub-токен | Строка diff `+ api_token = "ghp_TESTSECRET0123456789"` | В результате нет `ghp_TESTSECRET0123456789`, есть `[REDACTED]` | `app/review_service.py:14` — diff уходит в промпт без редакции |
| `SEC-1` | `redact()` вырезает приватный ключ | Блок между `-----BEGIN PRIVATE KEY-----` и `-----END PRIVATE KEY-----` | Тело ключа заменено на `[REDACTED]`, маркеры допустимо сохранить | Правило `SEC-1`: «удаляются токены, пароли и приватные ключи» |
| `SEC-1` | `redact()` вырезает пароль в строке подключения | `postgres://user:Passw0rd@host:5432/db` | Сегмент пароля заменён на `[REDACTED]`, остальной URL цел | Правило `SEC-1` |
| `SEC-1` | `redact()` не портит обычный код | Строки diff без секретов | Выход побайтово равен входу | Ложное срабатывание исказит evidence и сломает `QA-1` |
| `SEC-1` | `ReviewService.review` вызывает `redact` до `llm.generate` | Diff с тестовым токеном, стаб `LLM` записывает полученный промпт | В записанном промпте нет исходного токена | `app/review_service.py:14` — сейчас порядок шагов отсутствует |
| `API-1` | Проверка длины отсекает большой diff | `diff` длиной 20 001 символ | Поднято исключение/результат, транслируемый в HTTP 413 | Правило `API-1`: порог 20 000 символов |
| `API-1` | Граница включительно | `diff` длиной ровно 20 000 символов | Проверка проходит, обработка продолжается | Правило `API-1`: «длиннее 20 000» |
| `OUT-1` | Сборка ответа даёт три обязательных ключа | Корректный черновик от стаба `LLM` | В результате ровно ключи `summary`, `risks`, `checks` | Сейчас возвращается `{"comment": answer}` — `app/review_service.py` |
| `OUT-1` | Список рисков усекается до трёх | Черновик с пятью валидными рисками | В `risks` три элемента, порядок сохранён | Правило `OUT-1`: «максимум три элемента» |
| `OUT-1` | Каждый риск имеет обязательные поля | Черновик с риском без `line` | Риск отброшен, в `risks` его нет | Правило `OUT-1`: поля `file`, `line`, `evidence`, `risk` |
| `QA-1` | Риск без доказательства не проходит фильтр | Риск с пустым `evidence` и текстом «код можно улучшить» | Риск отброшен | Плохой пример из [`CASE.md`](CASE.md) |
| `QA-1` | Риск с доказательством проходит | Риск с `file=app/review_service.py`, `line=14`, непустым `evidence` | Риск попадает в `risks` без изменений | Хороший пример из [`CASE.md`](CASE.md) |
| `REL-1` | Ошибка LLM превращается в контролируемый ответ | Стаб `LLM`, бросающий исключение | Возвращён объект по `OUT-1`, `risks` пустой, исключение не всплывает | `llm.generate` без `try/except` в diff |
| `REL-1` | Таймаут ограничен 10 секундами | Стаб `LLM` с задержкой 11 с (время подменено) | Вызов прерван на 10 с, возвращён контролируемый ответ | Правило `REL-1`: timeout 10 секунд |
| `SCOPE-1` | Сервис не содержит операций записи в GitHub | Публичный интерфейс `ReviewService` | Нет методов approve/merge/commit; зависимость от клиента GitHub отсутствует | Правило `SCOPE-1` |
| `OBS-1` | Лог-запись содержит только разрешённые поля | Успешный вызов с diff, содержащим маркер `UNIQUE_MARKER_42` | В записи есть `request_id`, длительность, статус; нет `UNIQUE_MARKER_42` и текста ответа модели | Правило `OBS-1` |

Инструмент: `pytest`. Стаб `LLM` реализует `Protocol` с единственным методом `generate`, поэтому доменный слой тестируется без сети.

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): P1-02.
- Что проверили и исправили сами: модель сгенерировала проверки только на happy path сборки ответа. Сами добавили негативные и граничные случаи, без которых правила не проверяются: 20 000 против 20 001 символа (`API-1`), отбрасывание риска без `line` (`OUT-1`), отсутствие маркера diff в логе (`OBS-1`) и проверку, что `redact` не портит обычный код — без неё легко получить фильтр, который вырезает лишнее и разрушает evidence. Проверку «`redact` вызывается до `llm.generate`» добавили отдельно: тестировать саму функцию недостаточно, если её можно обойти.
