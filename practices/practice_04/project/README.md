# «Сроки» — self-hosted трекер дедлайнов

Однопользовательское приложение для учёбы и работы: категории (курсы/проекты), дедлайны
с приоритетом и статусом, группировка по срочности, сводка и экспорт в календарь (`.ics`).
Бэкенд — Python (только стандартная библиотека) + SQLite, фронтенд — Svelte + Vite
(собирается в статику `frontend/dist`, которую раздаёт тот же Python-сервер).

## Запуск

Нужны Python 3.12+ и (для сборки фронтенда) Node.js с npm.

```bash
cd frontend && npm ci && npm run build && cd ..   # один раз и после изменений фронтенда
python3 backend/server.py
```

Откройте <http://127.0.0.1:8000>. База `data/app.db` создаётся и мигрирует автоматически.

## Фронтенд: сборка и dev-режим

Сервер раздаёт готовую сборку Vite из `frontend/dist` (`FRONTEND_DIR`). Если сборки нет,
API под `/api` работает как обычно, а на `/` и прочие пути сервер отвечает страницей 503
с подсказкой `cd frontend && npm ci && npm run build` (и пишет предупреждение в лог при
старте). Пересобранный фронтенд подхватывается без перезапуска сервера.

Кэширование: файлы `/assets/*` (имена с хэшем содержимого) отдаются с
`Cache-Control: public, max-age=31536000, immutable`, остальное (`index.html`, `favicon.ico`
и т. п.) — с `no-cache`, поэтому после пересборки браузер сразу получает новую версию.

Dev-режим с горячей перезагрузкой — Vite dev server, который проксирует `/api` на бэкенд:

```bash
python3 backend/server.py                       # терминал 1, бэкенд на :8000
cd frontend && SROKI_API=http://127.0.0.1:8000 npm run dev   # терминал 2
```

Адрес бэкенда для прокси задаётся `SROKI_API` (по умолчанию `http://127.0.0.1:8002`);
откройте URL, который напечатает Vite.

### Переменные окружения

| Переменная     | По умолчанию   | Назначение                          |
|----------------|----------------|-------------------------------------|
| `HOST`         | `127.0.0.1`    | адрес (авторизации нет — не открывайте наружу) |
| `PORT`         | `8000`         | порт                                |
| `DB_PATH`      | `data/app.db`  | файл SQLite                         |
| `FRONTEND_DIR` | `frontend/dist` | каталог собранной статики (Vite)   |
| `LOG_LEVEL`    | `INFO`         | уровень логирования                 |

Относительные пути считаются от корня проекта, а не от текущего каталога:

```bash
PORT=8001 DB_PATH=/tmp/sroki.db python3 backend/server.py
```

## API в двух словах

JSON API под `/api`, ошибки — `{"error": "...", "field": "..."}`:

- `GET /api/health` — проверка работы сервера;
- `GET|POST /api/categories`, `PATCH|DELETE /api/categories/{id}` — категории;
- `GET|POST /api/deadlines`, `GET|PATCH|DELETE /api/deadlines/{id}` — дедлайны.
  Фильтры списка: `status` (`todo|in_progress|done|open`), `category_id` (число или `none`),
  `q`, `from`, `to`, `sort` (`due|priority|created`);
- `GET /api/stats` — сводка: просрочено / сегодня / неделя / открыто / выполнено;
- `GET /api/export.ics` — экспорт в iCalendar.

Полный контракт — в [docs/PLAN.md](docs/PLAN.md).

## Календарь (.ics)

`/api/export.ics` отдаёт открытые дедлайны как события (начало — срок, длительность 30 минут,
время локальное, без часового пояса). Принимает те же фильтры, что и список, например
`/api/export.ics?category_id=1`. Если указать `status`, фильтр по умолчанию (`open`) заменяется.

- Разовый импорт: скачайте файл по ссылке «Экспорт в календарь» и откройте его в календаре.
- Подписка: добавьте в календарь (Thunderbird, GNOME/KDE, Apple Calendar) URL
  `http://127.0.0.1:8000/api/export.ics`, и он будет периодически обновляться. Облачные
  календари (Google и т. п.) до `127.0.0.1` не достучатся — для них подойдёт только импорт файла.

## Тесты

```bash
python3 -m unittest discover tests   # временная БД, сервер на свободном порту
pyright                              # проверка типов (pyrightconfig.json)
```

## Структура

```
backend/db.py      — соединение, миграции (PRAGMA user_version), репозитории, валидация
backend/server.py  — HTTP: роутинг, JSON, ошибки, статика, экспорт .ics, main()
frontend/          — исходники Svelte + Vite; dist/ — сборка (её раздаёт сервер)
tests/             — test_db.py, test_server.py (unittest)
data/app.db        — база (не в git)
```
