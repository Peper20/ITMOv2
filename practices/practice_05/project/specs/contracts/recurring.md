# Общий контракт: повторяющиеся дедлайны

Согласован между командой UI (`specs/002-recurring-ui`) и командой логики
(`specs/001-recurring-logic`) по их черновикам `contracts/ui-needs.md` и `contracts/api.md`.
Источник истины для обеих спек и кода. Маршруты не меняются, `API_VERSION` = `"1"`.

## Решения согласования

| # | Расхождение | Решение | Кто решил |
|---|---|---|---|
| R1 | Периоды: UI — день/неделя/месяц, логика — ещё год | `daily`, `weekly`, `monthly`, `yearly`; интервал всегда 1 | человек |
| R2 | UI ждёт объект `next` в ответе, логика отдаёт только `next_id` | оба: `next_id` у дедлайна + `next` в ответе PATCH | человек |
| R3 | Выполнение с опозданием: логика — пропуск прошедших периодов | один шаг от срока экземпляра, без `now` | человек |
| R4 | Снятие отметки «выполнено» | следующий остаётся; повторная отметка второй не создаёт | человек |
| R5 | Текст ошибки `recurrence`: у логики — коды значений | текст для человека (UI показывает как есть) | оркестратор |
| R6 | UI допускал `next` при `POST` со `status: "done"` | `POST` следующий не создаёт, `next` в ответе POST нет | оркестратор |

## 1. Поля `Deadline`

| Поле | Тип | Запись | Значения |
|---|---|---|---|
| `recurrence` | `string \| null` | POST, PATCH | `null`, `"daily"`, `"weekly"`, `"monthly"`, `"yearly"` |
| `next_id` | `int \| null` | только чтение | id экземпляра, созданного при выполнении этого; `null` — нет или удалён |

Поля есть во всех ответах с дедлайнами. Без `recurrence` в POST → `null`. `next_id` в теле
запроса → `400`, `field: "next_id"`, «Неизвестное поле «next_id»» (существующая проверка).

## 2. Следующий срок

От `due_at` текущего экземпляра, время суток сохраняется, ровно один шаг (R3):
`daily` +1 день, `weekly` +7 дней; `monthly`/`yearly` — следующий месяц/год, день =
`min(опорный день, дней в месяце)`. Опорный день — день из `due_at`, когда пользователь задаёт
`due_at` или `recurrence`; следующий экземпляр наследует его (31.01 → 28.02 → 31.03;
29.02.2028 → 28.02.2029 → … → 29.02.2032). Опорный день в API не виден.

## 3. `PATCH /api/deadlines/{id}`

Переход `todo|in_progress` → `done`, если `recurrence != null` (с учётом значения из того же
запроса) и `next_id = null`, в одной транзакции:
1. текущий получает `status: "done"`, `completed_at`;
2. создаётся следующий: копии `title`, `description`, `category_id`, `priority`, `recurrence`;
   `due_at` по п. 2; `status: "todo"`, `next_id: null`;
3. текущему ставится `next_id`.

Ответ `200`: текущий дедлайн **плюс** поле `next` (R2):

```json
{"id": 7, "status": "done", "recurrence": "weekly", "next_id": 8, "...": "...",
 "next": {"id": 8, "due_at": "2026-11-13T18:00", "status": "todo", "recurrence": "weekly", "...": "..."}}
```

`next` — полный `Deadline`, только если экземпляр создан **этим** запросом; во всех остальных
PATCH `next: null`. Поле `next` есть только в ответе PATCH.

- `done` → `todo|in_progress`: меняется только текущий, следующий и `next_id` остаются (R4).
- Повторный переход в `done` при `next_id != null`: ничего не создаётся, `next: null`.
- Удаление следующего (`DELETE`) обнуляет `next_id` у предыдущего; новая отметка создаст снова.
- `{"recurrence": null}` выключает повтор; уже созданный следующий не трогается.
- Смена `recurrence`/`due_at` у выполненного ничего не создаёт.

`POST /api/deadlines`: принимает `recurrence`; со `status: "done"` следующий не создаётся (R6).
`DELETE`: удаляет только этот экземпляр. Диалогов «этот или вся серия» нет: каждый экземпляр —
обычный дедлайн. После снятия отметки (R4) у серии может быть два открытых экземпляра.

## 4. Ошибки

| Случай | HTTP | `field` | `error` |
|---|---|---|---|
| `recurrence` не из списка и не `null` | 400 | `recurrence` | `Повтор: выберите один из вариантов` (R5) |
| Следующий срок позже 9999-12-31 | 400 | `status` | `Невозможно вычислить следующий срок повтора` |
| Дедлайн не найден | 404 | — | как сейчас |

При любой ошибке транзакция откатывается: текущий не остаётся `done`, следующий не создан.
UI показывает ошибку `recurrence` под полем «Повтор», остальные — как сейчас.

## 5. Без изменений

`/api/stats` — формулы прежние (экземпляры — обычные дедлайны). `/api/export.ics` — каждый
экземпляр отдельным событием, без `RRULE`. Фильтры списка — без новых параметров.
