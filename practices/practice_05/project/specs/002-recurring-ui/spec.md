# Feature Specification: Повторяющиеся дедлайны — UI

**Feature Branch**: `002-recurring-ui`

**Created**: 2026-10-29

**Status**: Draft

**Input**: User description: "Повторяющиеся дедлайны. У дедлайна можно задать повтор (например, каждую неделю или каждый месяц). Когда повторяющийся дедлайн отмечают выполненным, появляется следующий." Зона этой спецификации — только интерфейс (команда 1). Правило вычисления следующего срока и хранение — зона команды логики; ожидания UI от неё — в [contracts/ui-needs.md](contracts/ui-needs.md).

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Задать повтор в окне дедлайна (Priority: P1)

Пользователь создаёт или редактирует дедлайн (например, «Отчёт по практике» каждую пятницу) и в окне дедлайна выбирает повтор из списка: «Не повторять», «Каждый день», «Каждую неделю», «Каждый месяц». Сохранённый повтор виден при следующем открытии окна.

**Why this priority**: без способа задать повтор остальная фича бесполезна.

**Independent Test**: создать дедлайн с повтором «Каждую неделю», закрыть, открыть снова — в поле «Повтор» выбрано «Каждую неделю»; сменить на «Не повторять» и сохранить — повтор снят.

**Acceptance Scenarios**:

1. **Given** открыто окно «Новый дедлайн», **When** пользователь выбирает «Каждую неделю» и нажимает «Добавить», **Then** дедлайн создан с этим повтором, окно закрыто, календарь обновлён.
2. **Given** открыт существующий повторяющийся дедлайн, **When** выбирают «Не повторять» и «Сохранить», **Then** повтор снят, значок повтора у дедлайна пропал.
3. **Given** открыто окно дедлайна, **When** пользователь проходит форму клавишей Tab, **Then** поле «Повтор» доступно с клавиатуры, стоит после «Срок» и до «Приоритет», меняется стрелками, у него есть подпись.
4. **Given** сервер отклонил значение повтора, **When** приходит ошибка с указанием поля повтора, **Then** текст ошибки показан под полем «Повтор», фокус переходит на это поле, окно не закрывается, введённые данные сохраняются.
5. **Given** окно открыто через быстрое добавление в ячейке, **When** дедлайн создаётся, **Then** он создаётся без повтора (быстрое добавление не меняется).

---

### User Story 2 — Выполнение повторяющегося дедлайна создаёт следующий (Priority: P1)

Пользователь отмечает повторяющийся дедлайн выполненным — флажком на карточке (неделя, окно дня) или кнопкой «Отметить выполненным» в окне дедлайна. Текущий дедлайн становится выполненным, появляется следующий, и пользователь сразу видит, на какую дату.

**Why this priority**: это и есть ценность фичи — не вводить регулярный дедлайн каждый раз заново.

**Independent Test**: отметить выполненным дедлайн «каждую неделю» на 06.11.2026 18:00 — появляется сообщение «Следующий — пт, 13 нояб., 18:00» с кнопкой «Показать»; на 13.11 в календаре есть новый открытый дедлайн с тем же названием и значком повтора.

**Acceptance Scenarios**:

1. **Given** повторяющийся открытый дедлайн на экране, **When** его отмечают выполненным, **Then** он показан выполненным, следующий появляется в календаре (если его дата в видимом периоде), сводка и боковая панель обновлены.
2. **Given** отметка выполнена успешно, **Then** показывается неблокирующее сообщение «Следующий — <дата, время>» с кнопкой «Показать», которое озвучивается экранным диктором (вежливо, без перехвата фокуса) и само исчезает через 8 секунд или по Esc/кнопке закрытия; фокус остаётся на флажке или кнопке, с которой работал пользователь.
3. **Given** сообщение о следующем показано, **When** нажимают «Показать», **Then** календарь переходит к дню следующего дедлайна и подсвечивает его, как при переходе из боковой панели.
4. **Given** отметка выполнена в окне дедлайна, **When** операция успешна, **Then** окно закрывается, фокус возвращается туда, откуда окно открыли, и показывается то же сообщение.
5. **Given** запрос на отметку идёт, **Then** флажок и кнопка «Отметить выполненным» неактивны до ответа; повторные нажатия не отправляют второй запрос.
6. **Given** нет связи или ошибка сервера, **When** отмечают выполненным, **Then** флажок возвращается в прежнее состояние, вверху показывается полоса ошибки с кнопкой «Повторить», следующий дедлайн не показывается.
7. **Given** статус меняют на «Выполнен» через список «Статус» в окне и нажимают «Сохранить», **Then** поведение такое же, как при кнопке «Отметить выполненным».
8. **Given** неповторяющийся дедлайн, **When** его отмечают выполненным, **Then** поведение не меняется по сравнению с текущим (никакого сообщения).

### User Story 3 — Видно, что дедлайн повторяется (Priority: P2)

В календаре, окне дня и боковой панели повторяющийся дедлайн отмечен значком повтора (круговая стрелка); у экранного диктора в описании дедлайна есть «повторяется каждую неделю» и т. п.

**Why this priority**: пользователь должен понимать заранее, что выполнение создаст новый дедлайн; без значка фича работает, но неожиданно.

**Independent Test**: создать по одному дедлайну с каждым вариантом повтора и без повтора; значок есть только у повторяющихся, всплывающая подсказка и озвучка называют правило.

**Acceptance Scenarios**:

1. **Given** повторяющийся открытый дедлайн, **Then** на полоске месяца и карточке недели/окна дня есть значок повтора, подсказка при наведении «Повторяется каждую неделю».
2. **Given** экранный диктор, **When** фокус на полоске или кнопке открытия дедлайна, **Then** в описании есть «повторяется <правило>» после приоритета.
3. **Given** повторяющийся дедлайн уже выполнен (следующий создан), **Then** у выполненного значок повтора не показывается — повторяется только актуальный экземпляр.
4. **Given** открыто окно повторяющегося дедлайна, **Then** под полем «Повтор» подсказка: «Когда отметите выполненным, появится следующий».

### User Story 4 — Вернуть выполненный повторяющийся в работу (Priority: P3)

Пользователь по ошибке отметил повторяющийся дедлайн выполненным и снимает отметку.

**Why this priority**: редкий, но путающий случай — можно получить два открытых дедлайна.

**Independent Test**: отметить повторяющийся выполненным, затем снять флажок; результат соответствует решению по уточнению ниже, и пользователю понятно, что стало со следующим.

**Acceptance Scenarios**:

1. **Given** повторяющийся дедлайн только что отмечен выполненным и следующий создан, **When** отметку снимают, **Then** [NEEDS CLARIFICATION: что делать со следующим экземпляром — удалить его автоматически (если его ещё не меняли), оставить оба открытыми или спросить пользователя?]. Допущение для черновика: следующий остаётся, показывается сообщение «Следующий дедлайн на <дата> остался» с кнопкой «Показать».

---

### Edge Cases

- Следующий дедлайн попадает вне видимого периода — в календаре его не видно, сообщение с «Показать» всё равно даёт к нему перейти.
- Следующий не проходит активный фильтр (категория, поиск) — сообщение показывается; «Показать» переходит к дню, фильтры не сбрасываются; если дедлайн скрыт фильтром, появляется существующая подсказка «ничего не найдено» со сбросом фильтров.
- Срок 31-го при повторе «каждый месяц», 29 февраля — дату следующего считает бэкенд; UI показывает ту, что пришла, и не вычисляет сам.
- Сильно просроченный повторяющийся дедлайн отмечен выполненным — следующий может сам оказаться просроченным; UI показывает его как обычный просроченный (в «Просрочено» панели).
- Повторяющийся дедлайн создают сразу со статусом «Выполнен» — UI ничего особого не делает, следует ответу сервера (если пришёл следующий — показывает сообщение).
- Удаление повторяющегося дедлайна удаляет только его; отдельного вопроса «удалить всю серию» нет, так как открытый экземпляр всегда один.
- Повторяющийся дедлайн удалён в другой вкладке и его отмечают выполненным — как сейчас: молча обновить данные (ответ «не найден»).
- Отметка выполнена на сервере, но ответ потерян (обрыв связи) — после «Повторить» или обновления календарь показывает реальное состояние; второй следующий не должен появиться (ожидание к бэкенду).
- Узкий экран (телефон, месяц — точки): значок повтора не показывается на точке, но есть в окне дня и в озвучке.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Окно дедлайна MUST содержать поле «Повтор» с вариантами «Не повторять» (по умолчанию для нового), «Каждый день», «Каждую неделю», «Каждый месяц» [NEEDS CLARIFICATION: достаточно ли этих вариантов или нужны «каждый год», «по будням», «каждые N недель»?].
- **FR-002**: Поле «Повтор» MUST иметь видимую подпись, быть доступным с клавиатуры в естественном порядке табуляции (после «Срок») и показывать текущее правило при открытии существующего дедлайна.
- **FR-003**: Ошибка сервера, относящаяся к повтору, MUST показываться под полем «Повтор» с переводом фокуса на поле; прочие ошибки — по существующим правилам (у поля или над формой).
- **FR-004**: Быстрое добавление в ячейке MUST создавать дедлайн без повтора, как сейчас.
- **FR-005**: Отметка повторяющегося дедлайна выполненным любым способом (флажок карточки, кнопка в окне, статус «Выполнен» + «Сохранить») MUST после успеха обновить календарь, панель и сводку и показать сообщение «Следующий — <день недели, дата, время>» с кнопкой «Показать».
- **FR-006**: Сообщение о следующем MUST озвучиваться вежливо (без перехвата фокуса), не перекрывать элементы управления, закрываться само через 8 с, по Esc или кнопке «Закрыть»; при наведении или фокусе внутри сообщения таймер останавливается.
- **FR-007**: «Показать» MUST переходить к дню следующего дедлайна и подсвечивать день так же, как переход из боковой панели.
- **FR-008**: Пока запрос на отметку не завершён, элементы отметки этого дедлайна MUST быть неактивны; повторное нажатие не отправляет запрос.
- **FR-009**: При ошибке отметки флажок MUST вернуться в прежнее состояние, ошибка — в полосе вверху с «Повторить» (существующее поведение); сообщение о следующем не показывается.
- **FR-010**: UI MUST показывать дату следующего дедлайна только из ответа сервера и не вычислять её сам.
- **FR-011**: Открытый повторяющийся дедлайн MUST отмечаться значком повтора на полоске месяца, карточке недели и окна дня, в списках боковой панели; значок дополнен подсказкой и текстом для экранного диктора «повторяется <правило>». У выполненных значок не показывается.
- **FR-012**: В окне повторяющегося дедлайна под полем «Повтор» MUST быть подсказка «Когда отметите выполненным, появится следующий».
- **FR-013**: Снятие отметки «выполнено» у повторяющегося дедлайна MUST вести себя согласно решению по User Story 4 и явно сообщать пользователю, что стало со следующим дедлайном.
- **FR-014**: Удаление повторяющегося дедлайна MUST работать как сейчас (два нажатия) и удалять только этот дедлайн; вопросов о серии нет.
- **FR-015**: Для неповторяющихся дедлайнов поведение UI MUST остаться прежним.
- **FR-016**: Окончание серии (дата окончания, число повторов) в этой версии не задаётся; остановить повтор можно только выбором «Не повторять» [NEEDS CLARIFICATION: нужно ли окончание серии уже в первой версии?].

### Key Entities

- **Дедлайн**: дополняется правилом повтора (нет / каждый день / каждую неделю / каждый месяц).
- **Следующий экземпляр**: новый открытый дедлайн, созданный при выполнении повторяющегося; наследует название, заметки, категорию, приоритет и правило повтора, имеет новый срок. UI узнаёт о нём из ответа на отметку выполнения.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь задаёт повтор у нового дедлайна не более чем за 1 дополнительное действие (выбор в одном списке) по сравнению с созданием обычного.
- **SC-002**: После отметки выполненным пользователь видит дату следующего дедлайна в 100 % успешных отметок, без открытия других экранов.
- **SC-003**: Все действия фичи (задать/снять повтор, отметить выполненным, перейти к следующему, закрыть сообщение) выполнимы только с клавиатуры.
- **SC-004**: Экранный диктор озвучивает правило повтора дедлайна и дату следующего после отметки.
- **SC-005**: При ошибке связи ни в одном случае пользователь не видит выполненным дедлайн, который на сервере не выполнен (после обновления состояние совпадает с сервером).
- **SC-006**: В проверке на 5 повторяющихся дедлайнах не появляется ни одного лишнего (дубля) следующего при двойном нажатии.

## Assumptions

- Варианты повтора — «Не повторять», «Каждый день», «Каждую неделю», «Каждый месяц»; итоговый набор согласуется в общем контракте с командой логики.
- Открытый экземпляр серии один: следующий появляется только при выполнении, заранее будущие экземпляры не показываются.
- Следующий наследует название, заметки, категорию, приоритет и повтор; статус — «Не начат».
- Правило вычисления даты (от исходного срока или от даты выполнения, конец месяца) — решение команды логики; UI его не дублирует.
- При снятии отметки (US4) до уточнения: следующий не удаляется, пользователь получает сообщение о нём.
- Экспорт в календарь (.ics) в этой фиче не меняется со стороны UI.
- Сообщение о следующем — новый неблокирующий элемент в стиле существующей подсказки «ничего не найдено», по одному за раз: новое заменяет предыдущее.
