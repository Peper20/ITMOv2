# Рефлексия

**Что согласовали.** Шесть решений R1–R6 (`project/specs/contracts/recurring.md`). Четыре принял
человек: периоды, `next` + `next_id`, один шаг при опоздании, следующий остаётся при снятии
отметки. После согласования UI и логика в коде не разошлись, сквозной сценарий прошёл без правок кода.

**Чему научились**

- **Расхождения видны только при сверке.** Каждая спека по отдельности была аккуратной, а проблемы
  нашлись, когда черновики положили рядом. Например, без R2 UI показывал бы «Следующий…» при
  каждой повторной отметке, и ни одна команда этого не заметила.
- **Важнее всего то, о чём команда не спросила.** Опоздание (R3) подняла только логика. Без
  согласования это решение тихо приняла бы реализация.
- **Контракт тоже надо ревьюить.** Команда логики нашла в нём противоречие с R4.
- **Сценарии спек становятся проверками.** Они почти дословно перешли в браузерные тесты, поэтому
  тесты проверяют договорённости, а не просто работу кода.

**Насколько SDD жизнеспособен.** Окупается там, где есть граница между сторонами: фронт и бэк,
две команды, публичный API. По сути это API-first, где контракт описан словами и сценариями.
Для мелких правок дорого: «Сбросить фильтры» — около 120 строк документов на 37 строк кода.
Ценность SDD в решениях человека, без них спека лишь фиксирует догадки модели.

**Что бы сделал иначе**

- Отдельный агент-ревьюер для спек и итоговой проверки — здесь ревью делал оркестратор.
- Прогнать `speckit-analyze` вместо ручной сверки spec/plan/tasks.
