Начнём с простого

Представь: у тебя одна папка с проектом

Обычно проект лежит в одной директории. Хочешь переключиться на другую ветку — делаешь git checkout. Но при этом все файлы меняются. Нельзя одновременно работать над фичей и фиксить баг.
📁 ~/projects/
📂 my-project/ main
Единственная рабочая директория
Хочешь поработать над feature/auth? Переключаешься — и весь контекст теряется. Билд сбрасывается, открытые файлы пропадают. Знакомо?
Решение

Git Worktree — несколько папок, один репо

Worktree создаёт отдельную физическую папку для каждой ветки. Все папки шарят один .git — коммиты и история общие, но файлы полностью независимы.
📁 ~/projects/ — после создания worktrees
📂 my-project/ main
Основная директория — стабильный код
📂 my-project-auth/ feature/auth
Worktree — отдельная папка, свои файлы
📂 my-project-fix/ fix/login-bug
Worktree — можно параллельно собирать и тестить
🔗 .git (общий) коммиты, stash, reflog — общие
Каждая папка — это полноценная рабочая среда. Можно одновременно открыть три терминала, три VS Code, три билда.

Быстрый квиз

Что происходит с .git при создании worktree?
A Создаётся полная копия репозитория
B Все worktrees шарят один .git
C Каждый worktree получает свой .git
Верно! Один .git на все worktrees — история, stash и reflog общие. Это экономит место и упрощает синхронизацию.
Не совсем. На самом деле все worktrees шарят один .git — это ключевое отличие от клонирования репо.
Зачем открывать Claude Code в каждом worktree отдельно?
A Claude Code не поддерживает несколько веток
B Для красивого логирования
C Каждая сессия работает со своими файлами и не мешает другим
Правильно! Claude Code работает в контексте текущей директории. Отдельный worktree = отдельные файлы = независимая AI-сессия.
Не совсем. Главная причина — каждая сессия работает в своей директории с отдельными файлами, не мешая другим.
