### Этап 2: Реализация бизнес-логики (45 минут)

#### Итерация 1: Структура данных (15 мин)

**Шаг 1: Подготовить контекст**

Вам нужна Pydantic модель для валидации входящих данных.

**Шаг 2: Промпт для модели**

**В чате Cursor:**
```
Мне нужно будет принимать JSON-запросы. 
Создай в файле main.py Pydantic модель с именем SubscriptionRequest. 

Она должна содержать:
- поле city типа str (обязательное)
- валидацию: city не должен быть пустым
```

**Шаг 3: Проверить результат**

**Ожидаемое добавление:**
```python
from pydantic import BaseModel, validator

class SubscriptionRequest(BaseModel):
    city: str
    
    @validator('city')
    def city_must_not_be_empty(cls, v):
        if not v or not v.strip():
            raise ValueError('city cannot be empty')
        return v
```

**⚠️ Возможные проблемы:**
- Агент может забыть валидатор → уточните промптом
- Может использовать старый синтаксис Pydantic v1 → попросите обновить

**✅ Checkpoint:** Модель создана с валидацией

#### Итерация 2: Эндпоинт POST /subscribe (20 мин)

**Шаг 1: Подготовить Acceptance Criteria**

Откройте вашу доску Miro/Notion из Практики 2. Найдите AC для "Подписка на уведомления".

**Пример AC (если у вас нет своих):**
```gherkin
Scenario: Успешная подписка на город
  Given пользователь не подписан на город "Moscow"
  When отправляется POST /subscribe с {"city": "Moscow"}
  Then возвращается статус 200
  And тело ответа: {"status": "subscribed", "city": "Moscow"}

Scenario: Ошибка при пустом поле
  Given пользователь отправляет запрос
  When поле city пустое или отсутствует
  Then возвращается статус 400
  And тело ответа содержит сообщение об ошибке
```

**Шаг 2: Важный промпт с управлением восприятием**

**В чате Cursor (ВНИМАНИЕ: используйте @main.py):**
```
@main.py 

Создай новый эндпоинт POST /subscribe с функцией-обработчиком.

Вот детальные требования:

[ВСТАВЬТЕ СЮДА ВАШИ ACCEPTANCE CRITERIA]

Не забудь:
- Использовать SubscriptionRequest для валидации
- Обработать ошибки валидации
- Вернуть правильные HTTP статусы (200 для успеха, 400 для ошибок)
- Вернуть JSON с полями status и city
```

**💡 Объяснение:**
- `@main.py` — явно указываем файл (управление восприятием)
- AC дают полную спецификацию (контекст для модели)
- Чек-лист в конце (гарантирует полноту реализации)

**Шаг 3: Проверить сгенерированный код**

**Ожидаемое добавление:**
```python
from fastapi import HTTPException

@app.post("/subscribe")
def subscribe(request: SubscriptionRequest):
    try:
        # Валидация происходит автоматически через Pydantic
        return {
            "status": "subscribed",
            "city": request.city
        }
    except ValueError as e:
        raise HTTPException(status_code=400, detail=str(e))
```

**Проверьте код-ревью:**
- ✅ Используется SubscriptionRequest
- ✅ Есть обработка ошибок
- ✅ Возвращается правильный статус
- ✅ JSON содержит нужные поля

**⚠️ Если чего-то нет — переходите к Итерации 3**

## ⚠️ Частые проблемы и решения

### Проблема: Агент генерирует неправильный HTTP статус

**Решение:**
```
Выделите return statement
Cmd+K: "Верни HTTPException с status_code=400 вместо 500"
```

### Проблема: Валидация не работает

**Решение:**
```
Промпт: "Добавь @validator для поля city, который проверяет, 
что строка не пустая и не содержит только пробелы"
```

### Проблема: Агент "забыл" часть требований

**Решение:**
```
Разбейте на шаги:
1. "Создай модель"
2. "Создай эндпоинт с валидацией модели"
3. "Добавь обработку ошибок"
```

### Проблема: curl возвращает HTML вместо JSON

**Причина:** Вы делаете GET вместо POST или неправильный URL

**Решение:**
```bash
# Проверьте метод и URL
curl -v -X POST http://localhost:8080/subscribe \
  -H "Content-Type: application/json" \
  -d '{"city": "Moscow"}'
```
