## Модель
- Веса: `Qwen3.6-35B-A3B-UD-IQ4_XS.gguf` (17,7 ГБ), MoE, квантизация **IQ4_XS**.
- ID в API: `qwen3.6-35b` (флаг `-a`), порт 9931, ключ из `~/.config/llama/api-key`.
- Контекст 131072, KV-кэш q8_0, один слот, 4 потока. Слои и эксперты раскладывает `--fit`.
- Запуск: `~/models/llm-qwen`. Сэмплинг: temp 0.6, top-p 0.95, top-k 20.
- Скорость генерации ≈17–20 токенов/с (в сессиях OpenCode ≈17,5).
- Облако не используется: `enabled_providers: ["llamacpp"]` в `lab/demo/opencode.json`.

### Обоснование выбора
Модель MoE с ≈3 млрд активных параметров: на 6 ГиБ VRAM и 32 ГиБ RAM она даёт приемлемые ≈17 ток/с, а качества хватает для tool calling (glob/grep/read) и русского языка. Модели 4B из `Modelfile` слабее и не отражают выбранный стек.

### Наблюдения
- **Ложная предпосылка (3) и отсутствующие данные (4) обработаны правильно**: модель сначала искала и читала файлы, не выдумывала CI и прямо сказала, что сведений нет.
- Лишние действия: в вопросе 5 шесть `glob` по расширениям `*.java/*.js/*.cpp/*.rs/*.go` в Python-проекте; в вопросе 2 модель читала `repo-system.txt`; в вопросе 1 добавила не запрошенный запуск `python3 test_service.py`.
- Узкое место — скорость: один слот и thinking. До отключения агента `title` один вопрос не успевал завершиться за 5+ минут, потому что генерация заголовка сессии тоже «думала» на той же модели.

## Ограничения и выводы
- Модель большая для 6 ГиБ VRAM: часть экспертов в RAM, ≈17 ток/с; thinking удваивает время ответа, но по решению он включён и фильтруется.
- Один слот (`-np 1`): параллельные запросы (заголовок, субагенты) выстраиваются в очередь.
- Результат одного прогона на пять вопросов не показывает разброса; повторы и температура не исследовались.
- `Modelfile` относится к Ollama; основной сетап (llama-server) его не использует.

## Проверка Modelfile через Ollama
`ollama create itmo-qwen36-check -f Modelfile` (Ollama 0.35.1) выполнилось успешно за 3 мин 11 с (GGUF 17,7 ГБ скопирован в хранилище). `ollama show`: архитектура `qwen35moe`, 34,7B, квантизация IQ4_XS, возможности completion/tools/thinking, параметры и SYSTEM из Modelfile применены. `ollama run` ответил; `ollama ps`: 18 ГБ, 74 % CPU / 26 % GPU при контексте 4096. Ответ показал влияние SYSTEM: на общий вопрос, не требующий данных, модель ответила «В предоставленных материалах нет ответа», то есть строгий system prompt из `Modelfile` вызвал лишний отказ (проверено одним запросом, без повторов). Проверочная модель после теста удалена (`ollama rm`), llama-server вернули на порт 9931.
